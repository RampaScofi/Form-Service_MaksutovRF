# Сервис форм (MVP)

Самообслуживаемый сервис форм для карьерной платформы: менеджер создаёт форму,
публикует её по уникальной ссылке, студент заполняет и отправляет, менеджер видит
ответы в админке.

Стек: Node.js >= 20, Express 4, чистый HTML/CSS/JS без сборщиков. Хранение —
JSON-файлы с атомарной записью. Каталог `data/` создаётся автоматически.

> ## ⚠️ Важно: админка без авторизации
>
> `GET /admin` доступен **любому**, кто достучался до сервиса. Формы, ответы и
> персональные данные студентов не защищены никак.
>
> Используйте сервис **только для локальной демонстрации** на своей машине
> (`http://localhost:3000`). Не выставляйте наружу: без HTTPS, без входа, без
> разграничения доступа и без rate-limiting. Для реальных данных пользователей
> нужна авторизация и отдельное решение по хранению.

## Требования

- Node.js >= 20 (проверено на v26.7.0)
- npm

## Установка

Из каталога `form-service/`:

```bash
npm install
```

Единственная зависимость — `express`.

## Запуск

```bash
npm start
```

Сервис поднимется на `http://localhost:3000`. Порт берётся из переменной
окружения `PORT`, по умолчанию 3000:

```bash
PORT=4123 npm start
```

Страницы:

| Адрес | Назначение |
|---|---|
| `/admin` | Админка: формы, конструктор, ответы |
| `/f/<slug>` | Публичная форма по ссылке публикации |

## Тесты

```bash
npm test
```

Выполняется `node --test tests/`. Тесты создают временную data-папку в
системном temp и удаляют её после прогона — боевой каталог `data/` не
загрязняется.

## Хранение данных

```
data/
├── forms.json              # массив форм
└── answers/<formId>.json    # массив ответов одной формы
```

- Запись атомарная: временный файл + `rename`, поэтому конкурентные отправки не
  теряют записи и файл не остаётся наполовину записанным.
- Повреждённый или пустой JSON-файл читается как пустой список — сервер не
  падает, а отдаёт пустые данные.
- `data/` в git не попадает (`.gitignore`).

## Основные эндпоинты

Админка:

- `GET /admin` — HTML админки
- `GET /api/forms` — список форм
- `POST /api/forms` — создать форму `{name, description, fields}`
- `PUT /api/forms/:id` — обновить форму
- `PUT /api/forms/:id/publish` — опубликовать (генерируется slug)
- `PUT /api/forms/:id/unpublish` — снять с публикации (slug сохраняется)
- `DELETE /api/forms/:id` — удалить форму вместе с ответами
- `GET /api/forms/:id/answers` — список ответов
- `GET /api/forms/:id/answers/:answerId` — один ответ
- `GET /api/forms/:id` — одна форма по id

Публичная часть:

- `GET /f/:slug` — HTML формы (404 для черновика и неизвестного slug)
- `POST /api/forms/:slug/submit` — отправка `{answers: [{fieldId, value}]}`

## Что не входит в MVP

Авторизация, CSV-экспорт, счётчики открытий/отправок, rate-limiting, правка
опубликованной формы с историей версий.
